The essentials

Asterisk PBX: the quick answer

What you will build

Asterisk is an open-source PBX that handles calls on a Linux computer. In this tutorial, Asterisk runs on Ubuntu and Linphone on Android registers as SIP extension 1001. When you dial 7000, Asterisk answers and plays a short “Hello World” recording.

We’ll build the PBX from source, create one SIP endpoint, load a simple dialplan, and make the internal test call. No public phone number, SIP trunk, or paid calling service is required.

01 / Fundamentals

What is Asterisk PBX?

Asterisk is open-source communications software that can turn a Linux machine into a PBX (Private Branch Exchange). A PBX manages call connections and can route calls according to rules you define.

In this example, the Asterisk server receives a call from Linphone and looks up the dialed number in its dialplan. For extension 7000, the dialplan answers the call, plays a sound recording, and hangs up. This small project introduces the same core components used in more elaborate VoIP systems.

02 / Core concepts

SIP vs. PJSIP vs. RTP: what is the difference?

These terms often appear together, but they describe different jobs. SIP is a signaling protocol. PJSIP is the SIP stack and channel-driver family used here by Asterisk. RTP transports real-time audio packets once media is established.

TermPlain-English explanation
AsteriskThe server software that controls and routes calls.
PBXA phone system that manages internal extensions and potentially outside calls.
SIPSession Initiation Protocol: registers devices and establishes, changes or ends calls.
PJSIPThe SIP implementation and Asterisk configuration modules used for SIP endpoints.
SDPSession Description Protocol: usually accompanies SIP messages to negotiate media details such as codecs and IP/port information.
RTPReal-time Transport Protocol: typically carries the actual voice packets.
CodecThe algorithm/format used to encode and decode audio; this example uses G.711 μ-law (ulaw).
ExtensionAn internal identifier such as the Linphone SIP extension 1001 or the test number 7000.
DialplanRules in extensions.conf that decide what Asterisk does when a number is dialed.

How do SIP registration and calling differ?

During registration, the softphone tells Asterisk where it can be reached and authenticates with its credentials. During a call, SIP messages such as INVITE and responses negotiate the session. In a typical established voice call, RTP carries audio; the exact media path depends on endpoint settings, network design and NAT behavior.

Common beginner confusion

SIP does not usually carry the voice waveform itself. Port 5060/UDP here handles SIP signaling; RTP uses a separate, configured UDP port range. These ports are example settings, not universal requirements.

03 / Call flow

How the Asterisk + Linphone call works

  1. Linphone on Android registers as SIP extension 1001 on the Asterisk server.
  2. You dial 7000 from Linphone. Asterisk receives the SIP call attempt and looks up the dialplan.
  3. The from-internal context answers the call, waits one second, and plays the hello-world sound.
  4. Linphone receives the audio; Asterisk hangs up when playback finishes.

05 / Practical setup

Install Asterisk 24 on Ubuntu from source

We’ll compile Asterisk from source on the Ubuntu computer. Run the following commands in its terminal. Use a fresh learning environment, not a server already hosting live calls.

Step 1 — Prepare your Ubuntu terminal

Terminal · create a project folder
mkdir -p ~/Desktop/Learning/asterisk/L1
cd ~/Desktop/Learning/asterisk/L1

This folder stores the Asterisk source files. If your system has no Desktop directory, choose another writable folder in your home directory.

Step 2 — Download the Asterisk 24 source

Terminal · official Asterisk distribution
wget https://downloads.asterisk.org/pub/telephony/asterisk/asterisk-24-current.tar.gz
tar -xzf asterisk-24-current.tar.gz
cd asterisk-24*/

The official asterisk-24-current.tar.gz archive provides the current source release within the Asterisk 24 series. The exact patch level may change over time.

Step 3 — Install compilation prerequisites

Terminal · build dependencies
sudo contrib/scripts/install_prereq install

The included script installs supported build dependencies for your platform. Review its output and address errors before continuing. It may install many packages.

Step 4 — Configure PJSIP and select modules

Terminal · configure & modules
./configure --with-pjproject-bundled
make menuselect

Inside the module-selection screen, confirm that the modules needed by the tutorial are available, including chan_pjsip, res_pjsip, res_rtp_asterisk, app_playback and the ulaw codec. Save and exit.

Step 5 — Compile and install

Terminal · compile Asterisk
make -j2
sudo make install
asterisk -V

The -j2 option runs two compilation jobs. Once installation finishes, asterisk -V prints the installed Asterisk version.

Step 6 — Generate sample configuration files (new installations only)

Terminal · new installations only
sudo make samples
ls -lah /etc/asterisk/

Do not overwrite a working PBX

make samples can overwrite existing configuration files. Only run it on a fresh disposable installation (or after backing up and confirming you want to replace those files). Official Asterisk documentation explicitly warns about this.

07 / SIP registration

Configure a PJSIP extension in Asterisk

Asterisk uses pjsip.conf to define SIP transport, endpoint settings, authentication, and registered contact information. Open the file:

Ubuntu terminal · edit pjsip.conf
sudo nano /etc/asterisk/pjsip.conf

For a fresh, isolated installation, configure one SIP endpoint named 1001. Replace the password placeholder with your own strong password, and avoid retaining conflicting sample sections in the same file.

/etc/asterisk/pjsip.conf · extension 1001
[transport-udp]
type=transport
protocol=udp
bind=0.0.0.0:5060

; SIP extension 1001
[1001]
type=endpoint
context=from-internal
disallow=all
allow=ulaw
auth=auth1001
aors=1001
direct_media=no

[auth1001]
type=auth
auth_type=userpass
username=1001
password=REPLACE_WITH_A_STRONG_PASSWORD

[1001]
type=aor
max_contacts=2
remove_existing=yes

How the PJSIP settings work

SettingPurpose
transport-udpListens for SIP signaling using UDP port 5060.
type=endpointDescribes extension 1001 and how Asterisk handles its SIP sessions.
context=from-internalRoutes calls from this endpoint into the matching dialplan context.
type=authDefines the SIP username and password used by Linphone.
type=aorHolds the registration contact information for the extension.
allow=ulawAllows the G.711 μ-law codec for audio.
direct_media=noKeeps media passing through Asterisk.

The label [1001] appears twice because the endpoint and Address of Record (AoR) are different object types. The separate [auth1001] section supplies its credentials.

Keep SIP private

bind=0.0.0.0:5060 listens on all IPv4 interfaces. Restrict connections to your trusted LAN or VPN. Depending on your Asterisk setup, changes to the PJSIP transport may need an Asterisk restart.

08 / Media transport

Set the RTP audio port range

Now set the UDP ports available for RTP, which transports audio independently of SIP signaling. Open rtp.conf:

Terminal · edit RTP settings
sudo nano /etc/asterisk/rtp.conf
/etc/asterisk/rtp.conf
[general]
rtpstart=10000
rtpend=20000

The 10000–20000/UDP range is a common lab configuration, not a set of public ports you should unconditionally open. If Ubuntu's firewall is enabled, allow SIP and RTP traffic only from your trusted LAN subnet using rules appropriate to your network, or connect through a correctly configured VPN.

Why one-way audio happens

A SIP call can appear to connect while its RTP packets cannot reach the intended destination. When sound is missing, inspect RTP, codecs, routing, NAT, firewalls and the endpoint's advertised media addresses—not just SIP registration.

09 / Call routing

Create the Hello World dialplan in extensions.conf

The dialplan tells Asterisk what should happen when somebody dials 7000. Edit the file:

Terminal · edit dialplan
sudo nano /etc/asterisk/extensions.conf

For the fresh lab configuration, define this context and test extension:

/etc/asterisk/extensions.conf
[from-internal]
exten => 7000,1,Answer()
 same => n,Wait(1)
 same => n,Playback(hello-world)
 same => n,Hangup()

Answer() accepts the call. Wait(1) pauses briefly. Playback(hello-world) plays the bundled audio prompt, and Hangup() ends the session. The leading spaces before same are optional here.

Where is the Hello World recording?

One commonly installed English sound file is /var/lib/asterisk/sounds/en/hello-world.gsm. You can check for it:

Terminal · check sound file
ls -l /var/lib/asterisk/sounds/en/hello-world.*

If nothing matches, inspect the installed sound packages and your sound-file language/path configuration. Sound availability depends on how Asterisk was built and installed.

10 / Start the server

Start Asterisk and inspect the CLI

To start Asterisk in the foreground with a verbose console on a lab system where it isn't already running:

Terminal · first start
sudo asterisk -cvvv

If Asterisk is already running, do not start a second instance. Connect to the active CLI instead:

Terminal · connect to active Asterisk
sudo asterisk -rvvv

Once you're at the asterisk* console prompt, try:

Asterisk CLI · reload & diagnose
pjsip reload
dialplan reload
pjsip show transports
pjsip show endpoints
pjsip show contacts
dialplan show from-internal

The first two commands reload their relevant configurations. The others display transports, endpoints, registered contact information and the dialplan entries Asterisk currently knows about. For changed transport binding settings, restart the Asterisk service if a reload does not apply them.

11 / SIP registration

Connect Linphone on Android to Asterisk

Linphone is a SIP softphone. Install it on Android, connect the phone to the same reachable private LAN as the Ubuntu server, and obtain the Ubuntu machine's local IP address:

Ubuntu terminal · local IP address
hostname -I

Use the private IP address that your Android phone can reach. If your phone is on a guest Wi-Fi network or network isolation is enabled, registration may fail until the devices can communicate.

In Linphone, select the option for a third-party SIP account (wording may vary by app version), then supply the following:

Linphone fieldSetting
Username / SIP ID1001
PasswordThe strong password you entered under [auth1001].
Domain / SIP serverYour Ubuntu computer's private, reachable IP address.
TransportUDP
Port5060, if requested separately.

Save the account, return to the Ubuntu Asterisk CLI, and enter:

Asterisk CLI · check registration
pjsip show contacts

Look for the contact belonging to extension 1001. Its SIP contact URI shows that Linphone has registered with Asterisk. A NonQual contact status can mean that periodic SIP OPTIONS qualification is disabled; it does not by itself mean registration failed.

12 / First SIP call

Dial 7000 and hear “Hello World”

Once Linphone is registered as extension 1001, open its dial pad and enter the test number:

Linphone · dial this number
7000

Asterisk receives the call, runs the from-internal dialplan, answers, waits one second, plays the built-in hello-world recording, and hangs up.

Successful result

You hear the “Hello World” recording in Linphone. This confirms that extension 1001 registered, Asterisk found the 7000 dialplan entry, and the greeting reached the softphone.

You can watch the call steps appear in the Asterisk console while the test call is running.

13 / Troubleshooting

Fix common Asterisk and Linphone setup problems

If the Hello World call does not work, inspect the SIP registration, dialplan, and audio configuration in that order.

ProblemWhat to check
Linphone does not registerCheck SIP username 1001, password, server IP, UDP port 5060, and LAN connectivity.
No SIP contact appearsRun pjsip show endpoints and pjsip show contacts in the Asterisk CLI.
Extension 7000 is not foundRun dialplan show from-internal and ensure 7000 is defined in extensions.conf.
No Hello World audioCheck the Asterisk sound files, the Playback(hello-world) line, codec support and RTP reachability.
Audio cannot reach LinphoneCheck your firewall rules, RTP port range, routing and any NAT settings.

Useful Asterisk CLI checks

Asterisk CLI · configuration checks
pjsip show transports
pjsip show endpoints
pjsip show contacts
dialplan show from-internal

For further details on SIP registration, see the Asterisk PJSIP troubleshooting guide.

14 / Calling basics

Do I need a phone number or SIP trunk?

No. The Asterisk extension 7000 is a local test number defined in your dialplan. Linphone can dial it over your private network without a purchased telephone number or SIP trunk.

A SIP trunk is generally used to connect a PBX with an outside telephony provider for calls to public mobile or landline numbers. It is not required for the Hello World example.

15 / Frequently asked questions

Asterisk PBX tutorial FAQ

Is Asterisk PBX free?

Asterisk is open-source PBX software. This internal Hello World calling exercise does not require a paid telephone number, though your computer and network still have operating costs.

What is PJSIP in Asterisk?

PJSIP is the SIP implementation used to define Asterisk phone endpoints, authentication and registration. The main file used here is pjsip.conf.

What is the difference between SIP and RTP?

SIP establishes and controls the call. RTP transports the audio, such as the Hello World recording played back to Linphone.

Which Asterisk version does this tutorial use?

This tutorial follows an Asterisk 24 source installation. The 24-current source archive can receive newer maintenance releases over time.

How do I check that Linphone registered successfully?

In the Asterisk CLI, run pjsip show contacts and look for a contact associated with extension 1001.

Why does extension 7000 not play audio?

Confirm that the from-internal dialplan contains the Playback(hello-world) command, the greeting audio file is installed, and the RTP audio path is reachable.

Do I need a SIP trunk for the Hello World call?

No. The test number 7000 is handled entirely by your local Asterisk server.

16 / Conclusion

You’ve built your first working Asterisk SIP call

You've installed Asterisk on Ubuntu, configured PJSIP extension 1001, connected Linphone on Android, and called 7000 to hear the Hello World recording. Along the way, you saw how SIP registration, dialplan instructions and RTP audio fit together.

These are the core building blocks of an Asterisk PBX. Keep this example as a reference for understanding configuration files and checking the path from your SIP client to the server.
